# 상세 설계서 — 단어 선택·자료 분석·품질 게이트

- 상위 문서: [아키텍처 정의서](../architecture.md) 5장
- 관련 결정: [ADR-004 업로드 시 제작 방식 선택](../decisions/ADR-004-preset-at-upload.md), [ADR-005 에이전트 프레임워크 미사용](../decisions/ADR-005-no-agent-framework.md)

## 1. 자료 분석 (제작 방식이 `auto`일 때)

| 항목 | 내용 |
|---|---|
| 입력 | 시스템이 고른 대표 페이지의 토큰. 초기 규칙: 텍스트가 충분한 페이지 중 앞 2쪽 + 나머지에서 균등 간격으로 최대 5쪽, 그리고 전체 페이지에서 글자 크기가 가장 큰 줄(제목급)만 추린 목록. 토큰 수 상한을 둔다 [권장, 실측 후 조정] |
| 출력 | 구조화 출력으로 `{doc_type, preset, reason}`. `doc_type`은 정해진 목록(강의 슬라이드, 교재·본문, 논문, 단어장·용어집, 기타) 안에서만 [권장] |
| 실패 | 형식 오류, 목록 밖 값, 타임아웃이면 기본 방식(개념 용어 [권장])으로 진행하고 사유를 기록한다. 예외를 던지지 않는다 |
| 사용자에게 | 결과 화면에 "자동으로 '개념 용어' 방식을 골랐어요(이유: …)"를 보여 준다. 마음에 들지 않으면 다른 방식을 지정해 새 빈칸 세트를 만든다 |
| 비용 | 문서당 Gemini 1회 추가 |

## 2. 품질 게이트

원칙: **품질의 바닥은 결정적 코드로만 판정한다.** 같은 입력이면 같은 판정이 나오고, LLM을 부르지 않는다. 코드가 재는 것은 품질 자체가 아니라 품질의 대리 지표이므로, 기준값은 실데이터로 보정한 뒤 확정한다.

### 2.1 칸 단위 (미달인 칸만 제거)

| 검사 | 초기 기준(가설) | 막는 실패 |
|---|---|---|
| 정답 노출 | 같은 페이지의 가려지지 않은 곳에 같은 단어가 있으면 제거하거나 `answer_group`으로 함께 가린다. 한국어는 조사를 떼고 비교 | 다른 줄을 보고 베끼기 |
| 토큰 정상성 | 하이픈으로 끝나는 토큰, 숫자·기호가 섞인 토큰, OCR 저신뢰 토큰 제거 | 줄바꿈으로 잘린 반쪽 단어가 정답이 됨 |
| 길이 | 영어 3자 미만·25자 초과, 한국어 2자 미만 제거 | 운으로 맞힘, 칸이 넘침 |

### 2.2 페이지 단위

| 검사 | 초기 기준(가설) | 막는 실패 |
|---|---|---|
| 생존 개수 | 칸 단위 검사를 통과한 수 ÷ 목표 개수(페이지 단어 수에 비례) < 60%면 미달 | LLM이 엉뚱한 단어를 골라 대부분 탈락 |

### 2.3 미달일 때 경로

형식 검증 실패와 같은 경로를 쓴다. Gemini 시도는 첫 시도와 재시도 1회를 형식·품질이 공유한다(재시도 때 오류·탈락 사유를 붙인다). 그래도 미달이면 규칙 기반 선택기를 쓰고, 그 결과도 같은 게이트를 통과해야 한다. 그마저 미달이면 그 페이지는 빈칸 없이 내보낸다. 어느 경우에도 예외를 던지지 않는다([신뢰성 설계](reliability.md) 1절).

### 2.4 후보 지표 (보정 후 추가 검토)

일반어 비율, 문서 핵심어 겹침, 세로 분포, 중복률. 일반어·핵심어 지표는 언어별 단어 빈도표(외부 자료)가 필요하다. 게이트를 늘릴수록 폴백 비율이 오르므로 처음에는 위 4개로 시작한다.

### 2.5 기준값 보정 (로드맵 2단계 완료 조건)

1. 실제 수업 PDF 5~10개에서 Gemini 결과와 규칙 기반 결과를 뽑는다.
2. 2명 이상이 칸마다 좋음 / 애매 / 나쁨을 붙인다.
3. 지표별로 좋음 칸과 나쁨 칸의 값 분포를 비교한다.
4. 기준값 후보마다 "나쁜 칸을 걸러낸 비율 / 좋은 칸을 잘못 버린 비율"을 구해 정한다. 둘이 잘 갈리지 않는 지표는 버린다.
5. Gemini와 규칙 기반 결과는 같은 PDF, 같은 라벨러, 같은 기준으로 비교한다.

### 2.6 운영 지표 (게이트가 아니라 경보용)

폴백 페이지 비율, 칸 탈락률, 사용자 정답률 분포, "이 빈칸 이상해요" 신고율. 페이지별 지표·시도 횟수·선택 출처(`gemini` / `fallback`)를 blank_sets에 기록한다. 폴백 비율이 평소보다 크게 뛰면 경보를 보낸다. 프롬프트나 모델을 바꿀 때는 기준 PDF 세트로 지표를 다시 재서 이전 값과 비교한다.

## 3. 남은 확인 사항

| 항목 | 상태 |
|---|---|
| 품질 게이트 기준값 | 로드맵 2단계에서 실데이터로 보정(2.5) |
| 대표 페이지 규칙·토큰 상한 | 실제 자료로 측정 후 조정 |
| `doc_type` 목록, 자동 실패 시 기본 방식 | [권장], 팀 확정 필요 |
| 한국어 단어 빈도표 출처·라이선스 | [미확인], 후보 지표를 추가할 때 확인 |
