# 상세 설계서 — PDF 처리·좌표 추출

- 상위 문서: [아키텍처 정의서](../architecture.md) 4장
- 관련 결정: [ADR-002 PDF 라이브러리](../decisions/ADR-002-pdf-library-pdfplumber.md), [ADR-003 래스터 리댁션](../decisions/ADR-003-raster-redaction.md)

## 1. 라이브러리 역할

| 라이브러리 | 용도 |
|---|---|
| pypdfium2 | 페이지 → 이미지 렌더링 |
| pdfplumber (pdfminer.six 기반) | 단어·글자 좌표, 폰트 정보 |

## 2. 좌표 규약

- pdfplumber 좌표는 **포인트 단위이고 `top`·`bottom`이 페이지 위쪽 기준**이다 [확인]. `y0`·`y1`은 페이지 아래쪽 기준이므로 쓰지 않고 `top`·`bottom`을 쓴다. 그러면 y축을 뒤집을 필요가 없다.
- 저장 좌표는 페이지 기준 0~1, 좌상단 원점. 화면에서는 컨테이너 대비 퍼센트로 배치한다.
- 폰트 크기·색은 pdfplumber의 글자 단위 정보(`fontname`, `size`, `non_stroking_color`)에서 가져온다 [확인]. 색 값의 형식(색 공간별 표현)은 pdfplumber `docs/colors.md`를 구현 시 참고.

## 3. 렌더링과 이미지 형식

| 항목 | 값 | 이유 |
|---|---|---|
| 렌더링 크기 | 긴 변 2000px [가설] | 화면 선명도와 30쪽 용량의 절충. bbox(0~1)에 이미지 폭·높이를 곱해 픽셀 좌표를 얻는다 |
| 저장 형식 | 원본·가린 이미지 모두 WebP, 품질 85 [가설] | PNG보다 훨씬 작다. 가린 자리는 단색이라 손실 압축으로도 글자가 비치지 않는다(로드맵 1단계에서 확인) |
| 추출 버전 | 렌더링 크기·형식·좌표 계산 방식이 바뀌면 `extract_version`을 올린다 | L2 재사용이 옛 이미지를 쓰지 않게 |

**빈칸이 없는 페이지**(글자가 거의 없거나 품질 게이트에서 모두 탈락)도 칠한 곳이 없는 "가린 이미지"를 만들어 저장한다. 원본 이미지에는 서명 URL을 주지 않는다는 규칙을 예외 없이 지키기 위해서다.

## 4. 글자가 없는 페이지 (OCR 도입 전)

- 텍스트 레이어의 글자 수가 20자 미만 [가설]인 페이지는 "글자 없음"으로 보고 빈칸 없이 내보낸다(`selection.source = none`).
- 문서 전체 페이지의 80% 이상 [가설]이 "글자 없음"이면 세트를 `failed`(`unreadable_pdf`)로 끝낸다. 스캔본일 가능성이 높다.
- OCR이 들어오면(로드맵 7단계) 이 판정은 "OCR로 넘길지"의 기준이 된다.

## 5. OCR 경로(스캔본)

로드맵 7단계. PaddleOCR 1순위 검토는 그대로. OCR 도구의 라이선스는 7단계 전에 확인한다 [미확인].
