# ADR-004: 제작 방식 — 업로드할 때 선택

## 상태
채택됨 (2026-10-27)

## 컨텍스트

빈칸을 만드는 방식(프리셋)은 자료에 따라 달라야 한다. 예: 어휘 문맥, 개념 용어, 수치·날짜, 정의. 사용자가 방식을 고를 수 있어야 하고, 고르지 않으면 시스템이 자료를 보고 정할 수 있어야 한다.

이때 갈리는 질문은 **사용자가 언제 고르느냐**다.

## 검토한 선택지

| 선택지 | 흐름 | 장점 | 단점 |
|---|---|---|---|
| **A. 업로드할 때 선택** | 업로드 화면에서 방식을 고른다(기본 "자동"). 작업 하나로 끝까지 처리 | 처리 도중 사용자를 기다리는 단계가 없다. 작업 1종, 상태 한 벌로 구조가 그대로다 | 자동이 고른 방식을 처리 전에 볼 수 없다 |
| B. 분석 후 중간 선택 | 작업 ①(수집·분석) → 추천 방식을 보여 주고 사용자가 고름 → 작업 ②(빈칸 생성) | 추천을 보고 고를 수 있다. 다른 방식으로 다시 만들 때 렌더링·추출을 재사용한다. PDF 파서가 작업 ①에만 남는다 | 작업 2종, 상태 두 벌, 선택 화면이 추가된다. 사용자가 고르지 않고 떠나면 중간 상태가 남는다 |

## 결정

A를 택한다. AI 모델을 고르듯 업로드할 때 방식을 함께 고르고, 기본값은 "자동"이다. "자동"이면 파이프라인 안에서 자료 분석으로 방식을 정한다(상세 설계는 아키텍처 정의서 5.3).

## 결과

- 결과 화면에 적용된 방식과 이유를 보여 준다. 마음에 들지 않으면 다른 방식을 지정해 새 빈칸 세트를 만든다.
- 다시 만들 때는 렌더링·좌표 추출부터 다시 한다. 이 비용이 문제가 되면, 페이지 이미지와 토큰을 문서 단위로 저장해 재사용하는 것을 검토한다. 이는 B의 장점 일부를 가져오는 개선이다.
- 처리 도중 사용자 입력을 받는 기능은 만들지 않는다. 이 결정은 ADR-005(에이전트 프레임워크 미사용)의 전제이기도 하다.
