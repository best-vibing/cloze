# ADR-007: 배포와 접속 — 시연 기기 + Tailscale, 한 주소, 아이디·비밀번호

## 상태
채택됨 (2026-10-27). 기존 결정 표의 "배포: VPS + Docker Compose"를 대체한다.

## 컨텍스트

이 서비스는 수업 기말 프로젝트로, **발표 시연까지 동작하면 된다.** 상시 운영할 필요가 없고 서버 비용을 쓰지 않는 편이 낫다. 반면 다음은 지켜야 한다.

1. 청중이 자기 휴대폰 브라우저로 접속할 수 있는 **공개 HTTPS 주소**
2. 공개 주소로 **Gemini 비용이 새어 나가거나 악성 PDF가 들어오지 않게** 막는 장치
3. 사용자별 문서·하루 한도·시도 기록이 동작하도록 **사용자 구분**
4. 평가 기준이 클라우드 배포를 요구하면 **짧은 시간 안에 옮길 수 있음**

## 검토한 선택지

**어디서 돌리나**

| 선택지 | 장점 | 단점 | 결론 |
|---|---|---|---|
| VPS | 항상 켜짐, "배포" 증거가 가장 확실 | 월 비용, 초기 설정 | 평가 기준이 요구할 때의 이전 대상으로 남김(아래 "클라우드로 옮길 때") |
| 정적 호스팅(Vercel 등) | 배포가 쉬움 | 워커·Redis·Postgres를 함께 돌려야 해서 정적 호스팅으로는 안 됨 | 탈락 |
| **팀원 기기 + Tailscale** | 비용 없음, 공유기·학교 방화벽 설정 불필요(바깥으로 나가는 연결만 씀) | 기기가 꺼지면 중단 | **채택** |

**클라우드로 옮길 때** (2026-10-28 검토. 평가 기준이 클라우드 배포를 요구할 때만 옮긴다)

| 방식 | 예 | 우리 코드에서 바뀌는 것 | 결론 |
|---|---|---|---|
| **VPS 한 대 + 같은 Compose** | AWS Lightsail, Hetzner, Oracle Cloud | 거의 없음. 기기만 바뀜 | **이전 대상** |
| PaaS(컨테이너 호스팅) | Fly.io, Render, Railway | 디스크가 매번 지워져 파일 저장소를 S3 호환으로 바꿔야 함. Postgres·Redis는 관리형을 따로 붙임 | 지금은 과함 |
| 대형 클라우드 관리형 조합 | Cloud Run + Cloud SQL + Memorystore + Cloud Storage | PaaS의 변경에 더해 설정이 가장 많음. 관리형 Redis가 비쌈 | 수업 규모에 안 맞음 |

PaaS·관리형으로 가는 길은 PostgreSQL을 골라서 열려 있다([ADR-008](ADR-008-database-postgresql.md)).

| 상황 | 쓸 곳 |
|---|---|
| 평가가 클라우드 배포를 요구하지 않음 | 시연 기기 그대로 |
| 발표 때만 클라우드가 필요함 | **시간제 VPS를 발표 전후 며칠만.** 발표 전날 만들고 끝나면 지운다. Lightsail 4GB는 시간당 약 $0.033 [제3자 자료]라 사흘에 $3 미만 |
| 발표 뒤에도 계속 운영함 | 그때 새 ADR로 정한다. 백업과 Gemini 유료 티어([ADR-010](ADR-010-llm-gemini.md) 재검토 조건)도 함께 |

**Oracle Cloud Always Free를 이번에 쓰지 않는 이유** (공식 문서 기준)

| 사실 | 우리에게 뜻하는 것 |
|---|---|
| Arm 무료 한도는 계정당 월 1,500 OCPU시간·9,000GB시간, 상시 켜 두면 2코어·12GB(2026-06에 절반으로 줄어듦) | 이 서비스가 4GB쯤 가져가면 그 계정의 다른 장기 용도 몫이 줄어든다 |
| 7일 동안 CPU(상위 95% 구간)·네트워크·메모리 사용률이 모두 20% 미만이면 회수될 수 있음 | 시연용은 대부분 놀고 있어서 회수 조건에 그대로 걸린다 |
| 무료 Arm 자리가 자주 부족함("Out of host capacity") | 회수되거나 지운 뒤 다시 만들기 어렵다. 무료 자격은 남아도 실제로는 못 쓰게 될 수 있다 |
| 중지했을 때 무료 자격을 잃는다는 규정은 없음 | 흔히 듣는 "중지하면 끝"은 자리 부족 때문에 생기는 현상으로 보인다 |

꼭 쓰려면 장기 용도가 없는 팀원 계정으로 만든다(한도는 사람마다 따로). Arm이라 Docker 이미지를 Arm용으로도 빌드해야 한다.

**공개 주소**

| 선택지 | 결론 |
|---|---|
| **Tailscale** | **채택.** 고정 `*.ts.net` 주소. 개발 중에는 Serve(같은 tailnet의 팀원만), 발표 때는 Funnel(누구나) |
| Cloudflare Quick Tunnel | 재시작마다 주소가 바뀜, 동시 요청 200개 상한 → Funnel이 안 될 때의 대비책으로만 |
| ngrok 무료 | 브라우저 앞에 경고 페이지를 끼워 시연·Lighthouse 측정을 방해 → 탈락 |

**웹 페이지를 어디서 내보내나**

| 선택지 | 결론 |
|---|---|
| **FastAPI가 웹 페이지·API·이미지를 한 주소로** | **채택.** 같은 출처라 세션 쿠키가 그대로 동작하고 CORS 설정이 필요 없다. 컨테이너가 가장 적다 |
| Caddy를 앞에 둠 | HTTPS는 Tailscale이 맡으므로 지금은 할 일이 거의 없다. VPS로 옮길 때 추가 |
| 프론트만 Vercel·GitHub Pages | 주소가 둘이 되어 CORS가 필요하고, 다른 주소 간 쿠키를 브라우저가 막는 경우가 많아(특히 Safari) 로그인 방식을 바꿔야 한다. API는 어차피 시연 기기에 있어야 한다 → 탈락 |

**사용자 구분**

| 선택지 | 결론 |
|---|---|
| Google 로그인 | 설정이 크다 → 후속(되면 좋음) |
| 초대 코드 + 이름 | 다른 기기에서 같은 사람을 다시 알아볼 수 없음 → 탈락 |
| 공용 계정 하나 | 모두가 같은 사용자가 되어 문서·한도·시도 기록이 의미를 잃음 → 탈락 |
| **아이디·비밀번호, 계정은 팀이 발급** | **채택.** 가입 기능 없이, 필요한 만큼 팀이 CLI로 계정을 만든다(발표용 시연 계정 포함) |

## 결정

- 팀원 기기에서 Docker Compose로 `api`·`worker`·`redis`·`postgres`를 띄운다. 파일은 Compose 볼륨(로컬 디스크)에 둔다.
- Tailscale을 호스트에 설치하고 `api` 포트를 노출한다. 개발 중에는 Serve, 발표·리허설 때만 Funnel.
- FastAPI가 웹 페이지(정적 파일)·API·이미지를 한 주소로 내보낸다. Caddy는 두지 않는다.
- 로그인은 아이디·비밀번호. 비밀번호는 솔트를 붙인 느린 해시로 저장하고, 로그인하면 서명된 세션 쿠키(HttpOnly, Secure, SameSite=Lax)를 준다. 서명만 믿지 않고 요청마다 사용자 존재와 `session_version`을 확인해서, 계정 삭제·비밀번호 재설정 때 세션을 바로 끊을 수 있게 한다. 가입 엔드포인트는 없다.
- CD는 끌어오기 방식이다. `develop` 머지 → CI 통과 → GitHub Container Registry에 이미지 → 시연 기기가 켜져 있는 동안 주기적으로 확인해 교체. 개인 기기에서 GitHub 실행기(self-hosted runner)를 돌리지 않는다.

## 결과

- 이미지는 오브젝트 스토리지의 서명 URL 대신, **API가 서명·만료를 확인한 뒤 직접 내보낸다**(`GET /images/{key}`). 오브젝트 스토리지는 "되면 좋음"이고, 붙이면 스토리지 어댑터만 바꾼다.
- 공개는 발표 때만 하므로 노출 시간이 짧다. 그래도 공개하는 동안은 로그인 + 서비스 전체 하루 한도 + 로그인 시도 제한이 함께 막는다.
- 발표 때 청중이 업로드까지 해 보도록 한도는 "발표 설정"(환경 변수)으로 바꾼다. 서비스 전체 Gemini 한도는 유지한다.
- 시연 기기가 꺼지면 서비스가 멈춘다. 발표 당일 점검 목록(절전·자동 업데이트 끄기)과 녹화 영상으로 대비한다.
- 평가 기준이 클라우드 배포를 요구하면 같은 Compose를 VPS로 옮긴다. 공개 주소는 Funnel을 그대로 쓰거나(Linux 지원) Caddy를 앞에 두고 HTTPS를 붙인다. VPS 메모리는 4GB 이상 [추정], 5주차 실측으로 정한다.

## 확인 필요

- Funnel이 실제 접속 IP를 헤더로 넘기는지(로그인 실패 한도를 IP로도 셀 수 있는지).
- Tailscale Funnel의 세부 한도와 시연 기기 운영체제 지원. 1주차에 `/health`를 Serve·Funnel로 띄워 확인한다.
